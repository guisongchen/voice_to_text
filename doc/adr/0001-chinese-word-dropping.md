# ADR 0001: 中文转录"吞词"的两个根因及修复（采集增益 + 插入方式）

- 状态：已接受
- 日期：2026-08-09（同日修订：补充插入阶段根因）
- 决策人：ccc

## 背景

使用过程中发现：中文语音输入时，整句话中经常有个别词被"吞掉"；英文基本无遗漏。排查后确认存在**两个独立的根因**，分别发生在音频采集阶段和文本插入阶段。转录（ASR）环节本身在增益修复后是正确的——判定依据是存档文本（`~/voice_recordings/*.txt`）内容完整。

## 根因一：麦克风采集增益过低（采集阶段）

**现象**：存档录音语音峰值仅 -39 ~ -50 dBFS（健康值 -12 ~ -6 dBFS），整体 RMS 低至 14~52（满幅 32767）。格式本身合格（16 kHz / 单声道 / Int16，无削波）。

**原因**：PipeWire 中 UGREEN USB MIC-CM769 源音量为 **0.50**。PipeWire 音量采用立方映射，0.50 对应线性增益仅约 12%（约 -18 dB）；该麦克风硬件增益固定 0 dB，无放大空间。信号极弱导致信噪比差：ASRCore 的峰值归一化不会改善信噪比（噪声同等放大），谱减降噪还会进一步吃掉低能量的中文清辅音音节。英文多音节、冗余度高，故未受影响。

**修复**：

```bash
wpctl set-volume @DEFAULT_AUDIO_SOURCE@ 1.0   # 0.50 → 1.00
```

**验证**：修复后实测语音峰值 -9.4 dBFS，ASRCore 转录完整无误。

## 根因二：xdotool type 合成 CJK 按键丢字（插入阶段）

**现象**：存档 txt 内容正确（"重大发现……"），但插入光标处的文本丢字（"重大现……"，"缓存文件夹"→"缓存文件"）。

**原因**：`xdotool type` 通过临时重映射空闲键码合成 CJK 字符，并为后续字符复用同一键码，与接收应用形成竞态，字符被静默丢弃。此外系统中**未安装 xclip/xsel**，导致原有剪贴板路径（仅 >200 字符时启用）从未真正执行，所有文本都走了会丢字的 xdotool 路径。

**修复**：

1. 安装 xclip：`sudo apt install xclip`
2. `inserter.py` 改为所有文本一律走剪贴板 + 粘贴快捷键（原子粘贴，杜绝丢字），粘贴后恢复原剪贴板内容；`xdotool type` 仅作兜底并加 `--delay 30ms`；删除 `CLIPBOARD_THRESHOLD` 配置。
3. 粘贴快捷键按焦点窗口类型选择：终端模拟器（gnome-terminal、kitty、konsole 等，`TERMINAL_WM_CLASSES`）用 **Ctrl+Shift+V**（终端里 Ctrl+V 被 readline 占用为 quoted-insert），其余 GUI 应用用 **Ctrl+V**；通过 `xdotool getactivewindow` + `xprop WM_CLASS` 探测。

**验证**：含生僻字（饕餮龍龘）和中英混排的测试文本插入一字不差，原剪贴板内容完好恢复。

## 决策总结

| 根因 | 层面 | 修复 | 性质 |
|---|---|---|---|
| 麦克风增益 0.50（立方映射 ≈ -18 dB） | 采集 | `wpctl set-volume 1.0` | 系统配置，无代码改动 |
| xdotool type CJK 键码复用竞态 | 插入 | 一律剪贴板粘贴 + 恢复；安装 xclip；终端窗口用 Ctrl+Shift+V | 代码 + 依赖 |

## 后果

**正面**

- 两个根因均被消除，中文输入链路（采集 → 转录 → 插入）各环节验证完整。
- 剪贴板粘贴为原子操作，插入速度也不再受文本长度影响。

**风险与注意事项**

- 插入文本会短暂覆盖用户剪贴板（约 0.5 秒后恢复）；粘贴期间用户若手动复制会互相干扰，概率极低。
- WirePlumber 会持久化麦克风音量，但其他混音器工具可能改动；音量 1.0 后无硬件余量，近距离大声说话需关注削波。
- 若 HUAWEI FreeLace Pro 蓝牙耳机成为默认输入源，电平与质量特性需单独确认。
- xclip 成为运行时依赖；未安装时退回 xdotool type（有丢字风险），守护进程日志会打印 "falling back to xdotool type" 警告。
- 未列入 `TERMINAL_WM_CLASSES` 的终端模拟器会收到 Ctrl+V 导致粘贴失败；遇到新终端时将其 WM_CLASS 加入配置即可。

**排查方法论（供日后参考）**

链路各环节可独立验证：存档原始 WAV（采集）→ 存档 TXT（转录）→ 光标处文本（插入）。哪一环开始出现差异，问题就在哪一环。本次先对比了 TXT 与终端显示，直接定位到插入阶段。

**后续可选项（未实施）**

- 录音电平自检：峰值低于 -30 dBFS 时输出告警日志。
- 插入后校验：读取插入结果与原文比对（依赖应用支持，可行性低）。

## 备选方案（已否决）

- **软件端数字增益/AGC**：对低信噪比信号无效（噪声同等放大），治标不治本。
- **更换 ASR 模型或调整模型参数**：问题在采集与插入两端，模型拿到的信号/输出的文本本身没有问题。
- **仅给 xdotool type 加 --delay**：可降低丢字概率但无法根除键码复用竞态，仅保留为兜底。
