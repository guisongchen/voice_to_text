# ADR 0002: 转录文本繁简归一化选型——OpenCC t2s 后处理

- 状态：已接受
- 日期：2026-10-11
- 决策人：ccc

## 背景

ASR 模型（Qwen3-ASR，`asr_core` 服务，默认 `qwen3-asr-0.6b`）对普通话语音的转写结果**字形不稳定**：同一说话人、同为普通话，有时输出简体中文，有时输出繁体中文，单次录音内部一致、跨次随机翻转。需求约束：

- 输出中的中文**必须是简体**；
- 输入语言不限于中文，可能是纯英文或中英混合，方案不能对输入语言做任何假设。

## 根因分析（为什么模型行为不可根治）

从架构上看，Qwen3-ASR 是 **音频编码器 + LLM 解码器**的生成式 ASR，输出为逐 token 采样：

1. **语音信号中不存在字形信息**——同一发音对应简/繁两种写法，声学上不可区分，"用哪种字形"是无约束的自由度，只能由训练先验（简繁混排的预训练语料 + 大陆/港台标注数据）和采样随机性填充；
2. **mode locking**：第一个中文字符的字形被采样确定后，后续 token 被前文强条件化，故单次输出内部一致；
3. **先验被内容拨动**：话题（涉台/古典）、口音（台湾腔 ↔ 繁体标注是训练数据中的真实相关对）都会改变翻转概率；
4. **system prompt 为空**时无任何约束。

这是生成式 ASR 的共性（Whisper 亦有同样现象），CTC 类模型因确定性 argmax 不存在此问题。结论：prompt 引导只能"降低概率"，模型微调成本巨大且随模型更换失效，**只有后处理归一化能"消灭可能"**。

## 决策

在 `voice_to_text` daemon 的转录结果出口处，用 **OpenCC `t2s` 配置**做确定性繁→简字符集转换，再进入插入与存档环节。

**实现要点**：

- 位置：`service.py` 的 `_transcribe_and_insert()`，`text = _to_simplified_chinese(result.get("text", "").strip())`，存档 txt 与光标插入共用转换后文本；
- 懒加载单例 `OpenCC('t2s')`，首次使用时初始化字典；
- opencc 不可用或转换异常时打印警告并回退原文，不阻断主链路（与 beep 失败静默的设计一致）；
- 依赖：`opencc-python-reimplemented`（纯 Python 实现，无需编译 C++ 库），已加入 `pyproject.toml`。

**`t2s` 行为边界**（实测验证）：

- 仅做字符集级转换（體→体、學→学），不做词组级语义替换（軟體→"软体"而非"软件"）；
- 英文逐字节通过；已是简体的文本为恒等映射；
- 纯字典 + 最长匹配分词，无 ML、离线、微秒级，符合 daemon 轻量定位。

## 备选方案（已否决/暂缓）

| 方案 | 结论 | 原因 |
|---|---|---|
| ASR context/system prompt 引导简体 | 暂缓 | ① `context` 参数会被原样注入 system message，"以下是普通话录音"是对输入语言的事实断言，对英文/混合输入构成错误前提，可能带偏转写；② 概率性偏置不保证结果；③ 需改动共享服务 `asr_core`（client→server→worker 透传），影响面大。若未来重启此方向，措辞必须只约束输出格式（如"转写结果中的中文一律使用简体汉字"）且需英文/中文/混合三组样本实测 |
| 模型微调固定简体输出 | 否决 | 成本高，且随模型更换（0.6b↔1.7B、未来换模型）失效 |
| OpenCC `tw2sp`（带词汇转换） | 否决 | 词组级替换（記憶體→内存、軟體→软件）改变了用词本身，超出"字形必须简体"的需求边界，违背忠实转写原则；若日后确认模型常输出台湾用词可再评估 |
| 不处理 | 否决 | 繁体输出出现频率实测不可忽略 |

## 后果

**正面**

- 中文输出 100% 简体，与输入语言、模型版本、解码随机性完全解耦；
- 对英文/中英混合输入零影响（非中文字符原样通过）；
- 实现集中在 daemon 一处，asr_core 共享服务零改动。

**风险与注意事项**

- `t2s` 不做词组归一，台湾式用词（网路、软体）会保留为简体字的台湾用法；可接受，升级路径为 `tw2sp`；
- 繁→简方向基本无歧义（多对一合并的逆向），误转风险极低；反向（简→繁）才有 发→發/髮 类歧义，本方案不涉及；
- 新增 Python 依赖 `opencc-python-reimplemented`，字典加载增加首次转录约百毫秒级开销（懒加载）；
- 存档 txt 与插入文本均为转换后内容，原始模型输出不再留档（如需对照模型原生行为，需在 asr_core 侧记录）。

## 验证

- 单元级：`_to_simplified_chinese` 对繁体句、中英混合、空串、None 的转换行为正确；
- 端到端：重启 daemon 后实际语音输入验证（含此前稳定复现繁体的语句）。
