# ADR 0001: 通过提升麦克风采集增益解决中文转录吞词问题

- 状态：已接受
- 日期：2026-08-09
- 决策人：ccc

## 背景

使用过程中发现：中文语音转录时，一整句话中经常有个别词被"吞掉"；而英文转录基本无遗漏。

初步怀疑方向包括音频格式、录音链路、ASR 模型中文能力。经排查：

**音频格式（合格）**

- 录音参数：16 kHz / 单声道 / Int16（`config.py` 中 `SAMPLE_RATE=16000, CHANNELS=1`）。
- 存档录音（`~/voice_recordings/*_raw.wav`）无削波（clip 0%），采样链路无断裂、无丢帧。

**录音电平（严重不合格）**

对近期 10 段存档录音的实测：

| 指标 | 实测值 | 健康值 |
|---|---|---|
| 语音峰值 | -39 ~ -50 dBFS | -12 ~ -6 dBFS |
| 整体 RMS | 14 ~ 52（满幅 32767） | 数百以上 |
| 低于 200 振幅的采样占比 | ~100% | — |

**根因**

PipeWire 中 UGREEN USB MIC-CM769 的源音量为 **0.50**。PipeWire 音量采用立方映射，0.50 对应的线性增益仅约 12%（约 -18 dB）；该麦克风硬件增益固定为 0 dB（`amixer -c 1 sget Mic` 显示上限即 0.00dB），无放大空间。两级叠加导致录到的信号极弱、信噪比很差。

**为什么英文正常、中文吞词**

- ASRCore 的 `AudioPreprocessor` 会做峰值归一化（至 -1 dBFS）+ 谱减降噪，但归一化不会改善信噪比——信号与噪声地板被同等放大；降噪还会进一步削弱弱音节。
- 中文音节短，且大量以低能量清辅音开头（q/x/s/sh 等），在低信噪比下整个音节被噪声淹没或被降噪吃掉；英文单词多音节、冗余度高，即使个别音节受损也能被模型恢复。

## 决策

在音频采集源头解决，而不是在软件链路中补偿：

```bash
wpctl set-volume @DEFAULT_AUDIO_SOURCE@ 1.0   # 0.50 → 1.00
```

并确认麦克风硬件 mixer 已为 100%（`amixer -c 1 sset Mic 100%`，实测其上限即 0 dB）。

不修改 `voice_to_text` 与 `asr_core` 的任何代码。

## 验证

修复后实测 8 秒录音：语音峰值 **-9.4 dBFS**（余量健康、无削波）。送 ASRCore 转录，结果完整无误（"你能听到我说话吗？"）。

## 后果

**正面**

- 中文转录吞词问题的直接根因被消除，录音信噪比恢复正常。
- 无需改动代码，无回归风险。

**风险与注意事项**

- WirePlumber 会将设备音量持久化到其状态文件，重启后保持；但其他混音器工具（pavucontrol、GNOME 设置等）可能再次改动该值。
- 音量设为 1.0 后无硬件级余量，若用户近距离大声说话需关注削波（实测 -9.4 dBFS 尚有充足余量）。
- 若 HUAWEI FreeLace Pro 蓝牙耳机成为默认输入源，录音链路会切换到该设备，电平与质量特性完全不同，需单独确认。

**后续可选项（未实施）**

- 在 `recorder.py` 或守护进程中增加电平自检：录音峰值低于 -30 dBFS 时输出告警日志，便于第一时间发现增益被改动。

## 备选方案（已否决)

- **软件端数字增益/AGC**：ASRCore 已有峰值归一化，但对低信噪比信号无效（噪声同等放大），且降噪会吃掉弱音节——治标不治本。
- **更换 ASR 模型或调整模型参数**：问题在采集端，模型拿到的是已经劣化的信号，换模型无法解决。
